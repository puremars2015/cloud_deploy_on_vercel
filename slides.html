三個階段，逐層加上去

每一層都能獨立驗證。先確認前一層會動，再往上疊。

1

靜態網站

一個 index.html。不用建置流程，Vercel 直接服務根目錄。

2

Serverless API

api/ 目錄下每個檔案就是一個端點，自動編譯成 function。

3

資料庫

Neon Postgres，透過 Marketplace 連結，連線字串自動注入環境變數。

Step 1

準備 repo

最小可部署單位就是一個 HTML 檔。沒有框架、沒有 npm、沒有建置。

# 專案根目錄
.
├── index.html      → /
└── vercel.json     選用：網址與標頭設定
  • index.html 必須在根目錄，Vercel 找不到就給你 404
  • vercel.json 可設乾淨網址與安全性標頭
  • 這個階段完全不需要 package.json
驗證方式　本機跑 python3 -m http.server 3000，瀏覽器開 localhost:3000 看得到就過關。
Step 2

匯入到 Vercel

全程在網頁上完成，不需要安裝 CLI。

  1. 開 vercel.com/new，用 GitHub 帳號登入
  2. 在 Import Git Repository 找到你的 repo，按 Import
  3. 清單裡沒有？點 Adjust GitHub App Permissions 開放該 repo 的存取權
  4. Framework Preset 選 Other，Build Command 與 Output Directory 全部留空
  5. 按 Deploy，十幾秒後拿到 <專案名>.vercel.app
Step 3

Git 整合怎麼運作

接好之後就不用再手動部署，push 即上線。

Production

push 到 main → 自動部署到正式網域。

Preview

開 PR 或 push 其他分支 → 產生獨立預覽網址，bot 會留言在 PR 上。

先看 Preview 再合併　預覽環境跟正式環境同一套設定，能驗證的東西完全一樣，但不會影響線上。
Step 4

加上後端 API

建一個 api/ 目錄，一個檔案就是一個端點。純靜態專案也能直接混用。

// api/hello.js  →  /api/hello

export default function handler(req, res) {
  res.status(200).json({
    message: "Hello from the backend!"
  });
}
  • 支援 Node.js、Python、Go、Ruby
  • 前端用 fetch('/api/hello') 直接打，同網域不用處理 CORS
  • 有相依套件就加 package.json，Vercel 會自動安裝
Step 5

接上 Neon Postgres

走 Vercel 內建整合，全程不用自己複製連線字串。

  1. 專案頁 → Storage 分頁 → Create Database → 選 Neon
  2. 方案選 Free，Region 挑離使用者最近的（台灣選 Singapore）
  3. 建立後選擇要連結的專案，Production / Preview / Development 三個環境都勾
  4. 按 Connect —— 這一步做完，DATABASE_URL 才會注入專案
最常卡住的地方　建立資料庫 ≠ 連結到專案。沒按 Connect，環境變數不會出現。
Step 6

建立資料表，然後 Redeploy

建立資料表

開好資料庫 ≠ 有資料表。到 Neon Console 的 SQL Editor 執行一次建表語法。

重新部署

環境變數是部署時注入的。設定完之後既有的部署讀不到，要到 Deployments 按 Redeploy。

create table if not exists messages (
  id         bigint generated always as identity primary key,
  name       text        not null,
  body       text        not null,
  created_at timestamptz not null default now()
);
陷阱 ①

正式站一片空白

部署成功、狀態 Ready，但打開網址是 404。

原因

Vercel 的 Production Branch 預設是 main。程式碼還在功能分支上沒合併，main 的根目錄沒有 index.html。

解法

合併 PR 進 main，或先用 PR 的 Preview 網址驗證。別去改 Production Branch，那只是繞過問題。

怎麼判斷　到 Deployments 看最新一筆部署的分支與 commit，跟你以為上線的東西對不對得起來。
陷阱 ②

已合併的 PR 不會再更新

PR 合併之後又往同一個分支推 commit，以為 PR 會跟著更新。不會。

PR 合併
分支內容進 main
→
繼續 push
新 commit 上分支
→
PR 不動
新 commit 不在 main
解法　已合併的 PR 是結束狀態，無法承載新工作。後續變更要另開一個新的 PR。
陷阱 ③

環境變數名稱對不上

不同整合、不同版本注入的變數名稱不一樣，程式碼卻只認一個。

// 整合可能注入其中任何一個
DATABASE_URL
POSTGRES_URL
DATABASE_URL_UNPOOLED
POSTGRES_URL_NON_POOLING
// 依序找第一個有值的
const name = VARS.find(
  (k) => process.env[k]
);
檢查方式　Settings → Environment Variables，確認名稱與程式碼讀的完全一致，以及三個環境都有勾。
陷阱 ④

FUNCTION_INVOCATION_FAILED

最難查的一個：錯誤處理寫好了，卻永遠不會執行。

問題
// 模組最外層 —— 匯入時就執行
const sql = neon(process.env.DB_URL);

export default function handler(req, res) {
  if (!process.env.DB_URL) {
    // ← 永遠跑不到的死碼
    return res.status(500).json({ ... });
  }
修正
// 第一次用到時才建立，並快取
function getSql() {
  if (cached) return cached;
  if (!url) throw new Error("缺連線字串");
  cached = neon(url);
  return cached;
}
原理　連線字串缺漏時 neon() 會拋例外。寫在模組層級，function 在匯入階段就初始化失敗，handler 根本沒被呼叫，錯誤處理形同不存在。
除錯

出問題時的判斷順序

直接打 API 端點，用回傳內容定位是哪一層壞掉。

看到什麼代表去修哪裡
{"messages":[]}全線正常只是還沒有資料
找不到連線字串變數沒進到 functionConnect Project／Redeploy
資料表不存在連得上但沒建表Neon SQL Editor
FUNCTION_INVOCATION_FAILED模組載入就崩潰Runtime Logs
404部署裡沒有這支 function確認部署的 commit
小技巧　Vercel 錯誤頁的 request ID 中間那段是 Unix 毫秒時間戳，解出來就知道這筆錯誤發生在你修正之前還是之後。
認識工具

Serverless 的邊界

一句話總結：API 端點沒問題，常駐服務不行。

適合

  • REST / JSON API、表單處理
  • 藏第三方 API key
  • Webhook 接收端
  • Cron 排程工作

不適合

  • WebSocket server、背景 worker
  • 寫入本機檔案系統並期待保留
  • 記憶體內狀態跨請求共用
  • 長時間批次運算
收尾

上線前 checklist

  • index.html 在根目錄，且已經在 main 上
  • Deployments 最新一筆的 commit 就是你要上線的那個
  • 資料庫已 Connect 到專案，三個環境都勾
  • 資料表建好了，不只是資料庫建好了
  • 環境變數設定完成後重新部署過
  • 初始化程式碼不在模組最外層，錯誤能被攔截並回傳可讀訊息

每一層都能單獨驗證 —— 遇到問題時，先確認是哪一層，再動手。
